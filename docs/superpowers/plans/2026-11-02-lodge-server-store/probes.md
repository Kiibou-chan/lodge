# Probes for the server-store plan

Run on 2026-11-02 with Bun 1.3.14, Kysely 0.29.7, and `uv run --frozen` (Python 3.13), in a scratch folder holding the files in `probes/` (with `bun install`), or from the repository root for the Python ones; outputs are quoted as printed.
The plan cites them as "probe N"; "plan 1's probe N" is an item of `../2026-11-02-lodge-server-core/probes.md`.

1. `bun p1-text.ts` (a `text` column through Kysely over `bun:sqlite`, `strict: true`): `lone_low differs: 61 30062`, `lone_high differs: 61 1f462`, `nul same`, `crlf same`, `astral same`, `bom differs: 61`.
   A lone surrogate is corrupted together with the character after it, and a leading U+FEFF is dropped, so a file's text does not survive a `text` column.
2. `bun p2-blob.ts`: the bytes `ef bb bf 61 80 ff 00 0d 0a` in a `blob` column come back as a `Uint8Array`, `same true`; and the raw driver binding `"\uFEFFa"` to a `text` column stores `hex(v)` = `61`, so the BOM is dropped when the text is bound, not when it is read.
3. `bun p3-tx.ts` (one connection): two transactions and a read started together log `a begin; a insert after 0; b begin; b insert after 1; reader saw 2`, so Kysely's SQLite driver runs one transaction at a time on its connection and a query waits for an open transaction; triggers `before update` and `before delete` raising `events are append-only` refuse `update e set who = 'x'` and `delete from e` with that message.
4. `bun p4-two.ts` (two connections on one file, WAL, `busy_timeout` 2000): a deferred transaction that reads, lets the other connection commit, and then writes fails with `database is locked`; a compare-and-set whose first statement is `update heads set rev = base + 1 where project = 'p' and rev = base`, run after the other connection moved `rev`, updates `0` rows and fails nothing.
5. `uv run --frozen python docs/superpowers/plans/2026-11-02-lodge-server-store/probes/defaults_filled.py . app` (plan 1's probe 26, for the `app` package): `Committed` 7 calls leave a default out, `Gate` 4, `Read` 6, `Shown` 0, `Listed` 4, `Added` 4, `Written` 3.
6. `uv run --frozen python docs/superpowers/plans/2026-11-02-lodge-server-store/probes/edit_decision.py` (lodge 0.2's app over `tests/app/support.py`'s project, one state): an `add` of `draft("d-aaaaaa")` with its statement replaced gives `outcome check failed [(5, 'd-aaaaaa: statement of a published decision was changed; a correction is a new decision that replaces it')]`, one with its reasoning shortened gives check 5's `reasoning of a published author decision was changed` message, and afterwards `show flags ()` and `problems ok True`: an edit of a decision sent through `add` is refused and leaves the store clean.
7. `uv run --frozen --quiet python -c "…"` with lodge 0.2's `content_hash` and `bytes.decode("utf-8", "surrogateescape")`: `content_hash('a\udc80\n')` is `518254327818`; the bytes `80ff` decode to U+DC80 U+DCFF, `c0af` (overlong) to U+DCC0 U+DCAF, `e282` (truncated) to U+DCE2 U+DC82, `eda080` (an encoded surrogate) to U+DCED U+DCA0 U+DC80, `f09f9880` to U+1F600, `f4908080` (beyond U+10FFFF) to U+DCF4 U+DC90 U+DC80 U+DC80, and `61e282ac62` to `a€b`; `content_hash('\ud83d')` raises `UnicodeEncodeError`, a `ValueError`.
8. `bun p5-cas.ts`: `update heads set rev = rev where project = 'p' and rev = :base` reports `base 7: updated rows 1` and `base 6: updated rows 0`, so a compare that leaves the value as it is still tells a matching base from a stale one.
